# Glass Markdown Note Context

## Current Direction

Build LumaNote, a native macOS SwiftUI sticky note app focused on one compact frosted-glass note that can stay at the edge of the screen.

The selected visual direction is a fusion of the generated `Bottom Rail Note` and `Slim Strip Note` concepts:

- One resizable frosted-glass note, not a dashboard.
- Content area takes priority.
- A slim bottom rail holds the main controls.
- The opacity slider runs from 0% to 100%.
- The bottom rail includes a compact file switcher for recent Markdown/text files plus Save As for the current note.
- Extra controls stay behind compact icon buttons or popovers.
- Clipboard suggestions appear as a compact top-bar island/popover, not a large permanent panel.

## Required Product Behavior

- Markdown note editing with live save.
- Markdown should render live inside the editable note body, not through separate edit/preview modes.
- Adjustable note opacity. New default note opacity is 60%.
- Adjustable theme color for the app's accent tone.
- Customizable global shortcuts for toggling the note, showing the note, hiding the note, and opening the clipboard library.
- App-level Chinese/English UI language switch in Settings. This changes app chrome text, not the user's Markdown content.
- Clipboard history saved locally after explicit app setting enables monitoring.
- Clipboard detection suggestions for URL, email, phone, address-like text, macOS local file paths, labeled codes such as verification codes or order/tracking numbers, and labeled free text after a colon.
- Polished SwiftUI/macOS visual style with frosted glass and subtle slide/fade behavior.

## Implementation Notes

- The note opacity slider controls the glass/readability layers, not the whole NSWindow alpha. Text and controls intentionally stay readable.
- The compact settings copy distinguishes shell visibility from glass texture: shell visibility controls the main shell and a reduced white haze contribution, while glass texture mostly controls highlights, edges, subtle refraction, and only a small added material thickness. Avoid letting the glass texture slider make the note read as a pure white sticky note. Current main-shell ranges: note opacity slider input 1%-100%, glass texture slider input 0%-100%, shell material opacity about 8%-60%, white haze about 0.6%-16.6%, theme tint/refraction about 0.5%-7.4%, and shell border about 18%-98%. New default glass texture strength is 10%. The 2026-06-15 semantic split experiment was rejected visually; keep this closer-to-original formula unless the user asks for a new direction.
- In-window floating panels are mutually exclusive. Opening the clipboard library, file switcher, more/settings panel, or top clipboard extraction actions should close the other floating panels; clicking outside a panel or leaving the note window should close any transient panel.
- Settings and the compact More menu include a Markdown editor font-size slider. It persists under `editorFontSize`, defaults to 15.5 pt, clamps to 11-28 pt, and the live Markdown styler scales headings, inline code, code blocks, lists, and task checkboxes from that body size.
- Markdown editing uses `MarkdownRenderingEditor.swift`, an editable `NSTextView` that live-styles the Markdown source. It saves plain Markdown.
- Markdown compatibility notes for GitHub are documented in `docs/markdown-compatibility.md`. The app saves original Markdown text, but the live editor is a lightweight visual styler rather than a full CommonMark/GFM renderer.
- Recent Markdown styling additions include underscore italic, bold italic, tilde fenced code blocks, nested quote/list indentation, GitHub Alert headers, email/autolink styling, reference/wiki link styling, image-reference styling, highlight syntax, and emoji shortcode token styling.
- The Markdown editor's enclosing `MarkdownScrollView` disables AppKit's built-in vertical scroller and draws its own slim right-edge scroll indicator as an overlay subview. Do not return to subclassing `NSScroller` for this surface; AppKit can still hide or skip drawing it in overlay mode. The custom overlay draws only the floating thumb, not a separate track. It stays visible as a thin idle thumb whenever the content is scrollable, briefly becomes clearer and wider while scrolling or while the pointer is over it, then animates back to a visible low-opacity idle state after about 1 second. Scroll progress is calculated from the text layout manager's actual used height plus the document visible rect, with a re-entrancy guard around layout refreshes. The note body outer padding is biased left by about 10 px to visually balance the right-side scroll indicator.
- Markdown styling now avoids the duplicate full-document pass from SwiftUI `updateNSView` after user edits. Markdown regexes are cached as static rules, and the custom scroll indicator caches document height until text/layout width changes, so ordinary scrolling no longer repeatedly forces full text layout measurement.
- `- [ ]` and `- [x]` are rendered as clickable checkboxes while keeping the underlying Markdown text.
- Task markers should not use a tiny hidden font because that makes the insertion caret short near a task marker. The current implementation parses each task line into indentation width plus a fixed checkbox slot, then dynamically computes the hidden marker kern so `- [ ]`, `- [ ] `, `- [ ]  `, `- [x] `, and newly typed tasks occupy the same visual slot.
- Checkbox drawing should use `lineFragmentRect.minX + textContainer.lineFragmentPadding + parsed indentation width`, not marker trailing position or ad hoc constants. The `lineFragmentPadding` term matters because ordinary text starts after AppKit's text-container padding; omitting it makes checkbox left edges fail to align with non-task paragraph text.
- `MarkdownTaskTextView.insertNewline(_:)` handles task continuation. Pressing Return on a non-empty `- [ ]` or `- [x]` line inserts a new `- [ ]`; pressing Return on an empty task line exits the task list by deleting only the current line's task marker/content range, not by inserting or replacing with another newline.
- The Markdown editor disables `NSTextView` automatic text completion, text checking, link/data detection, spelling correction, smart insert/delete, quote substitution, dash substitution, and text replacement. Keep these off so macOS does not auto-continue a plain hyphen list after the app has exited an empty task item.
- The opacity slider now bottoms out at 1%, not 0%. The lowest state keeps a faint glass silhouette, border, and visible control rail so the note does not degrade into frameless floating text.
- The top empty drag area shows three narrower, thinner semi-transparent horizontal bars so users know they can drag there.
- The visible bars stay small, but the invisible `WindowDragView` now fills the full top drag strip and the bars ignore hit testing, so dragging directly on the visible bars should always hit the AppKit drag layer.
- `WindowDragView.swift` overrides `acceptsFirstMouse` so the drag strip can receive the first mouse/trackpad event even while QuietNote is inactive. This is intended to make three-finger dragging work without first focusing the app.
- The top island must not be implemented as a normal SwiftUI `Button`; it blocks three-finger dragging. Use `WindowClickDragView` for the island hit target so short clicks open clipboard/actions and drag gestures call `window.performDrag`.

- `NoteStore` tracks a current Markdown file URL and up to 8 recent file URLs. Opening a file loads it into the note, pushes it to the recent list, and switches live save to that file; Save As writes the current content to the chosen file, pushes it to the recent list, and then switches live save to the new path. The current path and recent paths are remembered locally for the next launch.
- `NoteStore` also persists lightweight note workspaces under `noteWorkspaces.v1`. Each workspace has a name, an ordered file list, and its last current file. Existing single-file/recent-file data migrates into a default workspace. Opening a new file or Save As adds that document to the active workspace; switching within a workspace does not reorder the list, so next/previous navigation stays predictable.
- `NoteStore` caches `displayTitle` and only publishes it when the extracted heading or filename actually changes. Debounced autosave writes are dispatched off the main actor; explicit `saveNow()` remains synchronous for close/open safety.
- The bottom-left file button is a switcher, not a direct open button. It uses a left-right arrows icon and opens an in-window glass panel anchored to the button; the panel starts with a workspace picker/new-workspace menu, then separate actions for creating a new Markdown file and opening an existing file, then the active workspace's document list for quick switching. New Markdown files are created as blank `.md` files, immediately switched into live-save mode, and added to the active workspace. Empty Markdown files should remain empty across relaunches instead of being replaced with the default Today template. The file switcher panel is taller than the compact settings menu, sized for up to 7 workspace documents when space allows, and uses a fixed readable glass backing so it stays clear over Markdown content instead of following the main note opacity.
- `DocumentSwipeMonitorView` installs a local AppKit event monitor from a zero-size SwiftUI bridge view. It listens only to this note window, ignores momentum scrolls, and treats a dominant horizontal two-finger trackpad gesture as next/previous document within the active workspace. It normalizes AppKit's horizontal delta so positive progress means "next document / current page moves left." Keep switch decision and visual page travel separate: the current switch threshold is 55px with an 8px lock threshold, while visual travel uses `progressTravelThreshold=220px` so the page moves slowly without making switching harder. Once the gesture locks as horizontal, the local monitor consumes subsequent scroll events by returning `nil`, so the Markdown editor cannot also scroll vertically during a document swipe. A fast early horizontal swipe can commit before the scroll phase ends when it happens within the first 0.16s / 4 samples, reaches the 55px switch threshold, has at least an 18px current horizontal delta, and beats vertical movement by 2.1x; after this direct trigger, remaining scroll events in the same gesture are consumed until ended/cancelled or idle cleanup. Progress is throttled at up to 120Hz with a small progress epsilon. The current Markdown surface and the target document preview follow the user's swipe, then snap back or commit on release. The target Markdown text is loaded once into a non-hit-testable preview editor while the gesture is active; the real current file only changes on commit, so canceled swipes cannot accidentally change the live-save target. After a successful swipe switch, `markChromeActivity(revealIfCollapsed: true, forceReschedule: true)` expands the top island so the new file title is visible before auto-hide resumes. The editor receives a `markdownRevision` value so parent-only animation updates do not force string comparison, Markdown restyling, or scroll-indicator refresh.
- Main control text and icons should be adaptive across light/dark appearance. Avoid hardcoding black or white foregrounds for top island, file switcher, clipboard library, more/settings menu, and shortcut sheet controls; prefer dynamic primary/secondary ink with tuned opacity so dark mode stays readable while the glass UI keeps the same softness.
- Clipboard monitoring is on by default for new users, can be disabled from the compact more menu or Settings, and immediately captures the current clipboard when enabled.
- Clipboard monitoring timer starts/stops with the setting and runs in the common run loop so UI interaction is less likely to pause polling.
- Clipboard detection regexes are cached, and clipboard history persistence writes a snapshot off the main actor with a short debounce. The clipboard library filters the visible list once per render rather than rescanning for the count, empty state, and rows separately.
- Clipboard library list performance is intentionally kept data-driven: each row and extracted-value chip receives immutable item data plus action closures, not `@ObservedObject` references to the whole store/settings. Clipboard items cache a bounded preview string for list layout, search indexing is built lazily only when the user searches, and the wrapping chip layout caches row measurements between `sizeThatFits` and `placeSubviews`. The library view must request only the currently displayed batch from `ClipboardStore.visibleItems(matching:limit:)`; do not hand SwiftUI the full history array and then slice it in the view. Preserve these lower-level optimizations when changing the clipboard page; do not remove features to improve smoothness.
- General performance notes: Markdown title extraction should stay allocation-light because it runs while editing; document swipe previews use a modification-date-checked cache so repeated swipes do not repeatedly read the same file; the custom Markdown scroll indicator uses cancellable idle/animation tasks so wheel events do not accumulate delayed work; the document-swipe gesture monitor keeps only one cancellable idle-finish callback alive during continuous scrolling.
- Clipboard library v2 supports local search, per-item delete, copy/paste actions, and Copy/Paste popovers on detected values. Its list is custom `ScrollView + LazyVStack`, not a default macOS `List`; individual clipboard messages should not be boxed as cards. Keep the list lightweight with thin separators between messages and hidden/non-dominant scroll indicators. Text inside clipboard surfaces should use dark ink colors instead of white/system-primary text, so the glass panel remains readable over bright Markdown content and in dark system appearance.
- In-window popups that cover the Markdown editor, including the clipboard library, file switcher, compact More/Settings panel, extraction actions panel, and shortcut sheet, should use a fixed readable glass backing. Do not tie these popup surfaces to `settings.noteOpacity`; the note body can stay quiet/transparent, but opened panels must be opaque enough to cover the text behind them.
- The bottom toolbar glass backing should use one continuous rounded rectangle shape for fill, tint, and border. Do not reintroduce a separate rectangular top highlight, because it creates a mixed straight/rounded-corner outline. Collapsed top/bottom chrome handles should keep only one crisp capsule border from `ExtractionIslandButtonModifier`; their click hint should be a soft fill/glow rather than a second stroked capsule.
- Top chrome hints use a custom inline delayed help bubble instead of native `.help`, because the app-level native tooltip delay is intentionally short for toolbar buttons. Keep the top drag/title island and collapsed top handle help delay at 1.5s unless the user asks to make every tooltip slower.
- Extracted clipboard values are shown under the source clipboard record as contextual chips. Do not reintroduce a top-level type grouping unless the user explicitly asks.
- Clipboard detail extraction chips should wrap into multiple rows instead of using horizontal scrolling, because sideways trackpad scrolling is awkward in the small sticky-note panel. Extracted values live inside a subtle glass shelf, and each value is a stronger capsule bubble with icon + extracted value + subtle action chevron. Avoid wrapping the whole clipboard message itself in another bubble/card.
- macOS local paths such as `/Users/ceshi/Applications/Codex Token Bar.app` are extracted as `File` detections, even when they contain spaces. File detections use a folder icon and "Open in Finder" action through `NSWorkspace.activateFileViewerSelecting`, not Maps or direct app launch.
- Label/colon values such as `地址：...`, `电话：...`, `邮箱：...`, or `备注：...` are processed before generic detection. Known labels are typed when the value validates; unknown or invalid labeled values fall back to copyable Text chips instead of being dropped.
- Clipboard detections are sorted by confidence first, then by their original text position. Regex/pattern-backed values such as phone numbers, emails, URLs, files, addresses, and labeled codes are high confidence and appear first in the same order they appeared in the copied text. Values that only exist because of a generic label/colon fallback, such as `备注：...` becoming Text, are low confidence and appear after those high-confidence detections.
- Do not extract arbitrary numeric values. `Number` is now reserved for labeled codes/identifiers, such as 验证码, 取件码, 订单号, 快递单号, invoice, tracking, ticket, or similar labels. Plain years, dates, counts, prices, decimals, or standalone numbers should not create chips or top-island suggestions.
- Phone extraction is restricted to 10-15 digits and excludes simple date-like formats such as `2026-06-07`.
- Address extraction must not hand the whole clipboard body to Maps when only a labeled address segment exists. Prefer the value after the address label/colon, and use generic address matching only for standalone address-like snippets.
- The top island normally shows the current note title. `NoteStore.displayTitle` uses the first Markdown heading when present, otherwise the actual saved filename.
- In title mode, the title text is centered inside the island. The right-side clipboard icon is the only title-mode hit target that opens the clipboard library; clicking the rest of the capsule should not open the library.
- The clipboard library should not use SwiftUI/macOS `.popover`; it now uses `clipboardInlineOverlay`, an in-window glass panel centered under the top island. This avoids system popover misplacement and uses a faster 0.16s snappy transition. Keep a little breathing room below the top capsule; the panel currently starts at about 40 px from the note top.
- When the clipboard library is open, its transparent dismiss backdrop must leave the top drag strip hit-test transparent. The user should still be able to drag the note from the top capsule/grip while the clipboard list is visible.
- When focus leaves LumaNote/the note window while the clipboard library is open, close only the clipboard library overlay. The note window itself should remain visible because `hidesOnDeactivate=false` is intentional.
- The compact settings/more menu should also avoid SwiftUI/macOS `.popover`. It uses an in-window glass overlay anchored to the bottom-right settings button, then clamps its panel position to the note bounds so it stays usable near screen edges. When it is open, its dismiss backdrop leaves the top drag strip hit-test transparent and the panel is kept below that strip, so three-finger dragging from the top remains available.
- The island's glass shell, border, highlights, icon button background, and shadows follow `settings.noteOpacity` through `islandOpacity = max(0.05, settings.noteOpacity)`. Do not apply global opacity to the island content: the title text and icons must remain readable and should not fade with note transparency.
- The island's title/detected summary text and adjacent symbols should be stronger than the glass shell, not faded. Treat "20%/35% stronger" as increased visual weight from a full-strength baseline, not as 20%/35% opacity. Title mode and detection mode both use dark ink text/icons with a subtle white highlight, so the current note title and extracted clipboard type summary stay readable on the light glass island over bright Markdown or desktop content.
- When the latest clipboard entry has extracted values, the top island temporarily switches from title mode to detection mode. Its popover supports Copy/Paste, plus Open URL, Send Email, Call, or Open in Maps where appropriate.
- Detection-mode hit zones are separated: the left grip area should only drag and must not open popovers, the middle detection content area opens extraction actions, and the right clipboard icon opens the clipboard library. Keep the detection island narrower than the note's rounded top edge; do not let it span into the window corner radius.
- Detection mode must read as an active clipboard extraction, not just a renamed title pill. Its capsule keeps the stronger theme-color border and subtle internal glass glow while showing a centered type summary such as `已提取：电话、地址`, not the specific extracted text. The detection island uses a fixed internal three-zone layout: left drag grip, centered type summary, and fixed right clipboard icon, so short or long extraction results do not pull the clipboard button around. When the user clicks the middle summary area, the actions panel is an in-window overlay, not SwiftUI/macOS `.popover`, so there is no extra system material behind it.
